# 线下活动与付费入场 · 第一版

2026-10-23：用户明确需要付费报名。活动入口延续投票页全屏人物影像、深色遮罩、荧光色重点和居中排版；活动列表、报名、订单、电子票、工作人员核销共用同一视觉系统。

## 用户流程

1. 从投票页进入线下活动，查看实际发布的活动、时间、场地、费用和剩余名额。未发布活动时显示筹备状态，不自动公布示例活动。
2. 填写称呼与手机号，确认费用和报名须知。服务端保存价格快照，创建待支付订单并短时保留名额。
3. 完成收款渠道的付款步骤；只有可信支付结果或经授权的后台到账核对才能出票。浏览器的“我已付款”不能直接触发成功。
4. 已支付票面展示活动信息、短票号和二维码，可在原浏览器找回。票面二维码与付款二维码用途明确区分。
5. 工作人员登录核销页，扫描或输入票号，先确认活动与报名信息，再核销。二维码被重复展示不代表重复入场许可，最终状态以服务器为准。

## 订单与运营边界

- 票价按人民币分保存，避免浮点误差；每场活动由管理员设置，改价不追改已有订单金额。
- 待支付保留名额30分钟，若报名截止更早则以截止为准；过期订单释放名额。已支付、待支付与核销数量分开统计。
- 同活动同手机号不能重复占用有效名额；重复提交与支付结果重复到达均须幂等。手机号尚未接短信验证，不能称为已验证身份。
- 未支付不生成可核销票；取消、退款中、退款完成或活动取消均不能核销。退款记录不是资金到账的证明，真实退款要以渠道结果或实际人工退款核实为准。
- 活动默认草稿，管理员确定信息后发布；不实施真实收款、退款或自动发布试验活动。
- 第一版使用现有管理员身份核销；独立工作人员权限、候补、优惠券、多人团报及转赠不在本轮范围。

## 收款接入待定

已向用户询问微信商户支付、人工收款核对或支付宝商户支付，待选择。尚未获得商户配置或收款码，不把订单页面或模拟支付视为真实收款上线。

如接微信商户支付，按官方[Native支付开发指引](https://pay.wechatpay.cn/doc/v3/merchant/4012791891)和[退款开发指引](https://pay.wechatpay.cn/doc/v3/merchant/4013071031)处理订单查验、关单和退款结果。服务端必须核验可信签名、商户身份、订单号及金额；不能仅依据前端跳转显示支付成功。具体渠道实现以最终选型为准。

## 入场与隐私

票据使用高熵签名凭证，二维码在本机生成，凭证放在链接fragment，避免进入服务器URL查询日志。公开票面仅展示脱敏手机号，不提供通过手机号查询他人票据的入口。

核销默认允许活动开始前2小时至结束，扫描只预览，明确点击后原子提交。网络失败不能显示核销成功；重复核销显示既有时间。支持短票号输入作为现场备用。页面内相机仅在浏览器支持且用户点击后开启；当前HTTP站点还可使用手机系统扫一扫打开核销链接。

二维码属于持有人凭证，第一版不承诺防截图转发或实名验票。换设备找回、人工异常核实应通过运营处理，不能以知道手机号作为取票授权。
