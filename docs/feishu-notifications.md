# 飞书群投票通知

2026-10-25更新：总开关现在覆盖新增投票、私密留言与公开留言。新公开留言按独立`comment`类型异步发送，卡片含昵称、城市、正文和提交时间；暂停期间或此次升级之前的留言不自动补发。详见[公开留言通知修复](comment-notifications-20261025.md)。下文原投票去重与快照规则保留。

更新：2026-10-22。新数据库默认关闭。本机已按用户授权配置机器人；当前自动通知仅针对新增有效投票，定时汇总尚未启用。

## 配置与使用

1. 在目标飞书群打开“设置 → 群机器人 → 添加机器人 → 自定义机器人”，取得 Webhook。配置步骤与限制以[飞书自定义机器人官方文档](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)为准（核对日期 2026-10-22）。
2. 登录网站 `/admin`，进入“飞书通知”，粘贴 Webhook。若机器人开启签名校验，一并填写签名密钥；如果使用关键词校验，可设置 `LEAN CLUB` 或 `薄肌俱乐部`，每条通知均包含这两个名称。使用 IP 白名单时，放行网站服务器的实际出口 IP。
3. 点击“保存设置”，再点“发送测试消息”。测试操作会真实发往已保存的群，关闭自动投票通知时仍可测试。入队成功不等于发送成功，请查看后续状态。
4. 开启“新增投票通知”并保存后，仅新投票自动通知。卡片包含品牌、通知类型、新增城市、总票数、深圳／珠海／广州各自票数及北京时间。
5. 点击“立即推送汇总”可随时发送当前三城票数；自动提醒关闭时仍可手动汇总。保存设置不会自动发消息。

已保存的 Webhook 和密钥不会回显。输入框留空保留原值；勾选“移除已保存的签名密钥”可清除密钥。更换 Webhook 时，如需签名校验必须填写新密钥，旧机器人的密钥不会自动沿用。

自动通知保存的是**本次新增投票提交后的票数快照**，不是模拟数据。重复提交、同 IP 被阻止的重复投票、取消确认和改选均不产生通知；改选只更新原票，下次新增通知或手动汇总会反映更新后的三城分布。尚未开启时发生的投票不补发历史通知。

卡片采用官方 `interactive` 消息与 JSON 2.0 结构，按[分栏容器](https://open.feishu.cn/document/feishu-cards/card-json-v2-components/containers/column-set)、[Markdown 组件](https://open.feishu.cn/document/feishu-cards/card-json-v2-components/content-components/rich-text)和[标题组件](https://open.feishu.cn/document/feishu-cards/card-json-v2-components/content-components/title)实现居中数字、三城等宽排列和类型色带；核对日期 2026-10-22。旧版改投任务不再领取或重试。

## 发送状态与恢复

投票与通知任务在同一个 SQLite 事务中保存，网络发送由 API 进程中的后台线程完成。重启后未完成任务继续处理；发送期间不持有数据库事务，不等待飞书才返回投票结果。

| 状态 | 含义 |
| --- | --- |
| `pending` | 已入队，等待发送 |
| `sending` | 已领取任务，正在请求飞书 |
| `retrying` | 暂时失败，等待自动重试 |
| `sent` | 飞书接口已返回成功确认，不代表群成员已阅读 |
| `failed` | 不可重试的配置错误，或已用完自动尝试次数 |
| `cancelled` | 因配置或通知策略变化取消，不再发送 |

每个事件最多自动尝试 5 次，失败后的等待间隔依次为 5、30、120、600 秒；签名、IP 白名单、关键词校验错误直接标记失败。点击“重试失败消息”会重新排入当前配置版本下的失败任务。后台约每 3 秒检查待发送任务，空闲时约每 10 秒刷新；切走标签或隐藏页面会停止界面轮询，服务端仍继续处理。

每次有实际配置变化（开关、Webhook、签名密钥），服务端增加配置版本并取消旧版本尚未发送或已经失败的任务，避免旧消息意外发到新群。关闭推送后再开启不会补发被取消的任务。已经开始的网络请求可能仍完成，无法撤回。

“最新通知”对应**最新入队事件**；`pendingCount` 包含等待、发送中及等待重试的事件，`failedCount` 为失败事件数。较早事件的重试可以晚于较新的通知送达，因此比较票数时应以消息内的事件时间为准。

投票去重与通知投递是两个不同边界：本地每次新增有效票只创建一个任务；飞书没有用于本接口的消息幂等键。若飞书已收到消息但响应丢失，或进程在成功响应后、记录成功前退出，自动重试**可能重复送达同一事件**，投票数不会因此重复累计。事件编号保留在后台任务记录中，不显示在卡片正文。

## 管理接口

全部接口要求有效管理会话。POST 还要求本站 Origin／Referer 与 `X-CSRF-Token`，错误返回 `{ "error": "可读错误说明" }`。配置与发送操作共享每 IP 每分钟 12 次限流。

| 方法与路径 | 请求／结果 |
| --- | --- |
| `GET /api/admin/feishu` | 返回下述安全设置对象 |
| `POST /api/admin/feishu` | 保存设置，200 返回安全设置对象 |
| `POST /api/admin/feishu/test` | 空 JSON 对象；202 返回 `{queued, notificationId, settings}` |
| `POST /api/admin/feishu/summary` | 空 JSON 对象；202 返回 `{queued, notificationId, settings}`；暂停自动通知时仍可使用 |
| `POST /api/admin/feishu/retry` | 空 JSON 对象；202 返回 `{queuedCount, settings}` |

保存字段：`enabled` 为必填布尔值；可选 `webhook`、`signingSecret` 为字符串，空值保留；`clearSigningSecret` 显式清除密钥；`clearWebhook:true` 清除全部机器人凭据，必须同时传 `enabled:false`，不能混用新的凭据值。后台页面提供保存、密钥清除和开关；清除整个 Webhook 为接口能力。

安全设置对象包括：

- `enabled`、`configured`、`hasSigningSecret`：布尔值。
- `webhookMasked`：固定脱敏地址；`updatedAt`：最近配置修改时间或 `null`。
- `pendingCount`、`failedCount`：任务数量。
- `lastDelivery`：最新入队事件或 `null`；字段为 `id`、`kind`（当前 `new/summary/test`，旧记录可能保留 `change`）、`status`、`createdAt`、`sentAt`、`attempts`、`error`。时间为 UTC ISO 字符串，界面按北京时间显示。错误为固定安全提示，不回传飞书原始响应或凭据。

服务端仅接受 `https://open.feishu.cn/open-apis/bot/v2/hook/…`（标准 443 端口可省略），拒绝其他域名、非 HTTPS、用户信息、查询参数和非标准端口；固定连接官方域名，不跟随 HTTP 跳转。签名按官方文档使用当前秒级时间戳、换行和密钥构成 HMAC-SHA256 密钥，对空内容签名并 Base64 编码。后台以约每 0.75 秒一个请求节流，并对失败实施退避。

## 数据、安全与验证范围

凭据存于 `CLUB_DB` 的 `campaign_feishu_config`，任务存于 `campaign_feishu_outbox`；默认数据库位于忽略提交的 `data/local.sqlite3`。数据库中的 Webhook 和签名密钥不是加密密文：服务器文件权限和备份访问权限必须按凭据保护。不要把数据库、备份、真实 Webhook 或密钥加入源码、截图或公开日志。导出调试资料前先脱敏；换机器人时在飞书端撤销旧 Webhook。

备份、恢复流程沿用[本地运行说明](campaign-local.md#数据和备份)，必须保留完整数据库。恢复备份可能恢复旧的待发送任务或旧配置；启动恢复实例前先核对是否应继续对原群发送。不要让两个恢复副本同时向同一真实群发送测试数据。消息不包含访客 ID、IP、管理员账号或个人联系方式。已发送与已取消记录会在后续入队时清理超过 30 天的历史，未发送任务保留。

本轮 87 项后端测试通过，其中飞书 25 项，使用临时数据库与模拟传输；上一轮的 82 项／飞书 20 项结果保留为历史记录。真实运行服务另验证一条新增投票卡片和一次用户授权的手动汇总，飞书均返回成功，两条任务均一次发送完成；当时快照均为深圳 1、珠海 0、广州 0。最新回归及实际数据变化见[重置与通知验收记录](campaign-reset-notify-20261022.md)。接口成功仅代表飞书接受消息，不代表群成员已阅读。
