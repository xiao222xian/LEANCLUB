# 学校、团体与个人资料：首轮实施

日期：2026-10-24。依据用户确认：主页保持现状，短信暂不开通；学校相关页面沿用主页白底、深灰、薄荷绿及简洁留白。当前为实现与本地验收记录，生产结果在发布完成后追加。

## 已实现

- `/schools`：紧凑标题、三种浏览视图、搜索与细线列表；去除大口号、前三名卡片、巨大总数和重复说明。保留社群人数排序、并列名次、国内/海外筛选及原学校/社群深链接。未填人数的团体仍可发现，人数与排名显示横线；个人不参加人数排名。
- `/join`：548px单列表单，学校/团体/个人类型；支持自由填写国内外学校、英文名称、所在地与独立团体。主表单最少字段，附加资料折叠；没有手机号登录依赖。
- 提交后取得私密管理链接，地址片段不发送到服务器日志。浏览器生成32字节随机凭证，数据库只保存摘要；以凭证和版本校验修改，网络重试幂等，同名不覆盖。兼容原版有效管理链接。
- 后台 `/legacy-admin#schools`：历史资料与新增资料合并为一个运营列表，按类型/审核状态过滤；新增、侧栏编辑、通过发布、退回补充、隐藏和修改历史。去除后台横幅图片/口号，统一白底、细线和薄荷绿按钮。疑似同名提示保留，未自动合并。
- 新增与修改先审核；旧公开版本在修改审核期间继续显示。撤回个人资料或联系信息公开许可立即生效。个人默认不公开；联系方式/二维码单独同意，后台不能替提交人扩大公开范围。
- 同名跨国家/城市不覆盖；一个学校可关联多个团体。未收录学校的团体审批时可一并建立学校资料。学校目录编号经服务端固定回环接口核对，新关联失败仍可按自由填写资料审核；旧59条已有学校编号保留。

## 数据与接口边界

当前两个域名仍使用152.136.108.87的同一数据库。沿用既有SQLite clubs作为公开资料权威源，以club_directory_meta新增类型/所在地/可见性/关联字段，directory_drafts保存待审核版本与私密联系数据；没有另建一套会与现有目录双写的公开记录。私密联系信息不写入旧公开表，隐藏同时沿用visible=0，以免旧程序回退时泄露。

- 公开：`GET /api/directory`、`GET /api/directory/:id`。
- 持管理凭证：`POST /api/directory/submit`、`POST /api/directory/manage`；同源约束、请求大小和频率限制。
- 管理：`GET/POST /api/admin/directory`、`GET/POST /api/admin/directory/:id`；复用原管理员会话，写入要求CSRF和同源校验。
- 原`/api/club/schools`仍只输出公开团体，原详情不返回私密联系信息；原同名匿名写入接口仍关闭。
- 新资料不自动写入若依教育学校字典，也不伪装为学校认证。若依的原会员申请/账号/活动/订单/财务模块没有迁移；本次统一的是网站历史资料和新增三类型资料的运营入口。
- 未接入邮件、短信、自动身份认领、管理链接找回或实体合并工具。失去原管理链接时仍须人工核对；同名提示不等于已确定重复。
