# 活动报名后端验收记录 · 2026-10-23

当前版本是付费订单与入场核销底座；收款渠道尚未选定、未连接真实支付或退款服务。未配置支付适配器时 `paymentReady=false`，后端拒绝创建收费订单。源码没有供客户端或管理员手动将订单改成 paid 的 HTTP 接口。

## 实测结果

- 全量 Python 测试 **127 项通过**（40.796 秒），其中新增活动模块 **19 项**。命令：`python -m unittest discover -s tests`。
- 验证草稿不公开、不接受报名；活动字段与价格整数分校验；订单报价快照；客户端期望报价不符返回409；已有请求幂等恢复原订单；客户端额外声明paid被拒绝。
- 验证同一手机号与访客隔离、并发抢最后名额不超卖、重复请求仅一单、30分钟/截止时间保留名额、超时释放、待付无可核销二维码。
- 验证付款后本地生成PNG二维码、URL fragment凭证、公开票面手机号脱敏、伪造票与站外链接拒绝；管理源校验/会话/CSRF；预览不核销、并发核销仅首次成功、重复返回原时间。
- 验证已付款申请取消进入待退款、旧票即时失效；取消活动关闭待付并让已付转待退款。待退款保留名额，避免把未完成退款宣称为已退款。
- 验证旧库升级保留投票、意见、管理员会话；原有意见/飞书相关回归测试继续通过。测试不连接真实飞书或支付服务。

## 本地交互验收边界

独立测试库在被 Git 忽略的 `data/events-qa-20261023/`。仅该目录的临时进程包装器注入内存测试适配器，演示活动明确标注测试，价格99元。`tests/test_campaign_events.py` 的 `synthetic_paid` 仅用于隔离数据库，直接构造合成收款状态；不属于运行时支付适配器，不通过HTTP开放，不证明真实到账、支付回调或退款能力。

真实上线收款仍需：选定渠道、凭据配置、可信服务端到账确认/金额核验/交易幂等、支付侧关单与迟到到账对账、退款执行和回调、真实小额端到端验收。客户端倒计时结束不能被当成支付平台已关单。此版本不作真实收款已验收的结论。
