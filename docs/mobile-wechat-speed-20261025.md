# 国内微信访问优化 · 2026-10-25

用户连续授权优化并上线，优先二维码；不购买云资源、不改 DNS、不清数据。

## 已核实的原因

- com 元数据 region-id=us-west-1；2 CPU，1,674MB 内存，约1,302MB可用，load 0.16/0.06/0.01，磁盘11%。当前样本不支持 CPU/内存不足；未取得云带宽套餐及用户手机真实网络瀑布图。
- com 静态站在美国西部，共用后台在国内152.136.108.87。原站HTTP/1.1，无回源连接池。
- 本机本轮HTML请求com1.96s、xyz0.156s；不同线路样本不能当作用户手机实测。旧版高DPR手机会选941px，图片等待个性化campaign接口，QR也受其阻塞。

## 实施

- com HTTP/2、TLS会话复用、16条回源keepalive；保留TLS校验、同源API与共用数据库。
- 增加仅含公开海报与当前群码元数据的 /api/campaign/presentation，无身份、Cookie、统计或投票字段。浏览器/com最多缓存15s，按群码到期时间缩短；个性化campaign、投票与管理接口继续不缓存。
- 首页和投票页优先预加载活动群PNG；手机浏览器缓存及页面Blob复用，点开后不重新下载。换码版本改变即失效；群码图片公共缓存仍最多30s，实时投票响应带当前配置。预加载不计入展示次数。
- 手机固定640px轻量WebP，不因DPR3自动下载941px。可见城市先加载，主图与QR完成后再顺序预热其余城市；省流量/2G不预热。
- 既有上传图按不可变新URL派生 -640-v2.webp（quality78），文件原子保存并复用，旧图和数据库不修改。未来上传也自动适用。

## 验证与限制

- 7项群码HTTP测试通过，包括公开引导接口无Cookie/无个性化字段、停用/过期与缓存；图片重编码与路径边界2项通过。相关JS语法通过。
- 本地390px/DPR3、180ms延迟和160KB/s模拟：QR预取在campaign个人响应前完成；点击入群仅发出展示统计，不再获取配置/图片。模拟不是微信真机实测。
- 真实公网发布/资源大小与命中结果记录在工作区06-delivery/releases/mobile-wechat-20261025/STATUS.md。
- 无法由软件优化保证中美线路稳定；如后续国内微信仍慢，应据实测评估靠近国内且线路合适的接入节点，先不升级CPU/内存。

配置依据：[NGINX HTTP/2](https://nginx.org/en/docs/http/ngx_http_v2_module.html)、[上游keepalive](https://nginx.org/en/docs/http/ngx_http_upstream_module.html#keepalive)，核查2026-10-25。
