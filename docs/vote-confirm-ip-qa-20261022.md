# 投票确认、IP 去重与后台刷新修复

日期：2026-10-22（Asia/Shanghai），仅本地开发，尚未发布公网。

## 问题实测

用户反馈无确认弹窗、同 IP 不应重复投票、后台一直显示 0。修复前只读检查用户库：0 条投票，主站与投票页各 3 次访问；没有投票写入步骤的限流记录。因此不是统计把已有票算成 0。旧版首次点击仅切换为“确认投给…”按钮，需第二次点击才提交；后台仅在打开和手动刷新时读取。

检查时 4180/5381 均无监听，本机服务已停止，浏览器保留页面也不能提交。无法从上述证据确定用户具体一次点击是否遇到来源错误或离线，不据此断言用户操作错误。

## 实施

- 点击投票后打开独立确认弹窗，明确城市、确认投票与返回选择；返回、Esc 和点击外部不提交。提交时锁定，失败留在弹窗，服务器成功后才显示已投。
- HTTP 投票强制使用服务端识别的 IP，规范化 IPv4/IPv6，数据库专用随机密钥 HMAC 后保存；随机密钥和历史 IP 认领随数据库保存。事务与唯一约束防止并发重复。
- 同 IP 新浏览器读取已有票，不能改投；原浏览器可改选但总数仍为 1。原浏览器换网络也不新增票，原 IP 不能再被新浏览器重复使用。共享公网 IP 会限制共享网络内的多个用户，这是用户明确要求的规则。
- 非破坏迁移保留旧票。历史缺 IP 的票无法追溯；原浏览器下次提交时补绑定。本轮用户库原先为 0 票，未删除、补造或导入测试票。
- 后台可见概览每 10 秒刷新，恢复可见/焦点、同源投票成功广播也触发读取；后台直接读取持久化票数。
- 新增 Windows 隐藏后台启动与定向停止脚本，避免启动终端结束后网页仍留着而服务停止。仅监听回环地址，日志/运行记录位于忽略目录 `data/runtime/`。

## 验证结果

后端全套 **62 项通过，17.575 秒**，包括新增 12 项 IP 测试：并发多 Cookie、同/不同 IP、原浏览器改选、换网络、IPv6/mapped、来源代理伪造、重启密钥稳定、旧库迁移、投完后后台立即读取。第一次整套运行有一次 Windows 连接发送中断 WinError10053，定向 24 项和最终完整 62 项重跑通过；没有将中断记为成功。

浏览器使用独立 `data/vote-confirm-qa-20261022/site.sqlite3`、4181/5382 与合成账号：

| 操作 | 实测结果 |
| --- | --- |
| 首次点击深圳 | 立即出现确认弹窗 |
| 返回选择 | 数据库仍为 0 |
| 确认深圳 | 页面显示成功，已打开后台未手动刷新便从 0 变 1 |
| 改投珠海前按 Esc | 原深圳票保留 |
| 确认改投珠海 | 后台深圳 0、珠海 1、广州 0，总数仍为 1 |
| 刷新原投票页 | 恢复已投珠海，可改选 |
| 同 IP 不同 Cookie 身份 | 显示该 IP 已投珠海，三个按钮禁止重复提交 |
| 320×740 | 弹窗宽 288，正文无横向溢出，确认和返回可见 |
| 后台运行 | 启动命令结束后独立进程仍监听；定向停止 QA 后用户服务继续可用 |

同 IP 不同身份的 UI 检查使用 localhost 与 127.0.0.1 的独立 Cookie 域；真实 HTTP 测试另外覆盖多个独立 Cookie 客户端。QA 中的票数与账号均非真实活动数据。

静态检查：Node JavaScript 语法、Python 编译、PowerShell 解析及 Git whitespace 检查通过。没有进行实体手机/微信/公网扫码验收。
