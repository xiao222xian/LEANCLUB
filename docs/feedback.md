# 意见箱

记录日期：2026-10-22。本文描述本轮本地实现；不表示意见箱版本已经部署。线上固定版本、HTTP/TLS及实际验收范围仍以[部署记录](deployment-152-136-108-87.md)为准。本轮没有向真实飞书群发送意见测试消息。

## 参与入口与后台

城市投票页 `/city-vote` 的“有个想法”打开意见弹窗，以当前城市海报作为背景。无需登录或填写联系方式，选择类型、城市后填写想法即可提交，不要求先投票，也不改变投票结果。

| 类型值 | 页面名称 |
| --- | --- |
| `activity` | 活动玩法 |
| `training` | 训练交流 |
| `other` | 其他想法，默认选项 |

城市可选深圳、珠海、广州或“不限城市”。首次打开预选当前展示的城市，用户可以修改。正文限制5–1000字，前后空白会去除；服务端按Unicode码点计数，并要求至少5个字母、数字、标点或符号，拒绝不允许的控制字符，保留换行及支持emoji连接的字符。

弹窗支持键盘、Esc、关闭按钮和点击外侧关闭，关闭后焦点回到入口。发送时禁用表单重复操作，成功显示“你的想法，收到了”。网络或校验失败保留当前内容；关闭再打开也保留未完成的草稿。草稿及重试标识仅在当前页面内存中，刷新或离开页面后不保留。提交前等待匿名访客初始化，避免首次加载与发送并发覆盖访客Cookie。

后台 `/admin` 新增“意见箱”：按“全部／待看／已看”筛选，最新意见优先，每页20条，支持翻页、手动刷新和标记已看／移回待看。待看角标在已登录且页面可见时约每30秒检查；发现新内容显示更新提示，由管理员刷新，不自动替换正在阅读的列表。标记状态不会删除意见或重新发送通知。本版没有回复、编辑正文、删除或公开展示功能。

## API契约

接口均返回JSON。写入须通过本站来源校验；后台读取需要管理员会话，后台状态写入还需要CSRF头。公开提交不要求管理员身份。

| 方法与路径 | 参数或请求体 | 返回 |
| --- | --- | --- |
| `POST /api/campaign/feedback` | `requestId`、`content`、`category`，可选 `city` | 新建201，幂等重试200；`ok,id,createdAt,duplicate` |
| `GET /api/admin/feedback` | `status=all\|new\|read`，`page=1`；两项可省略 | `items,total,unread,page,pageSize,totalPages` |
| `POST /api/admin/feedback/{id}/status` | 仅 `{"status":"read"}` 或 `{"status":"new"}` | 更新后的 `item` 与全局 `unread` |

以下仅为合成请求示例，不应直接向正式站提交：

```json
{
  "requestId": "8b367ebf-7021-4856-85aa-e41c756b2032",
  "content": "希望组织一次新手友好的训练交流。",
  "category": "training",
  "city": "shenzhen"
}
```

`requestId` 为带连字符的UUID，统一转小写；`city` 省略或为 `null` 表示不限城市，其余允许值为 `shenzhen`、`zhuhai`、`guangzhou`。未知字段、错误类型、重复JSON键或不合法内容会被拒绝；请求体上限32 KiB，须使用JSON内容类型。

列表项包含 `id,content,category,city,status,createdAt`；`id` 为32位小写十六进制，时间为UTC ISO字符串，页面显示北京时间。`total` 是当前筛选下的数量，`unread` 是全部待看数量。页码允许1–1000000，越界页返回空列表；`totalPages` 最小为1。筛选仅接受 `status,page`，不接受多次同名参数。没有面向匿名访客的意见读取接口，公开提交回执不返回正文或访客标识。

主要错误：400参数或内容无效，401管理员未登录，403来源或CSRF校验失败，404意见不存在，409相同提交标识对应不同内容，413请求体过大，415内容类型错误，429超过频率限制。重复设置同一已看状态是幂等操作。

## 幂等与限流

同一匿名访客、同一 `requestId`、相同规范化正文／类型／城市只保存一条意见，并返回原回执；重试不会再次占用成功提交额度或再次排队通知。相同标识改了内容返回409，需用新标识提交。前端在内容未变的失败重试中复用标识，修改任一提交字段后使用新标识。清除Cookie、更换浏览器或刷新后重新输入不属于同一幂等身份，仍受IP额度约束。

| 限制维度 | 滚动窗口额度 |
| --- | --- |
| 单个匿名访客成功提交 | 10分钟3条；24小时10条 |
| 同一来源IP成功提交 | 10分钟10条；24小时30条 |
| 同一来源IP请求保护 | 每60秒60次；适用于完成JSON解析后进入该提交接口的请求，包括内容校验失败及重复提交 |

成功额度检查、匿名访客创建、意见保存及通知入队在同一SQLite事务内完成。无效或超过成功额度的提交不增加访客记录、不设置新访客Cookie；事务失败不留下部分意见或通知。请求级保护先于访客创建，幂等重试仍受请求级保护。IP来自服务器现有可信代理配置，共用公网出口的用户共享IP额度，不能将IP计数视为独立人数。

## 飞书通知

沿用后台“飞书通知”的机器人与开关。机器人已配置且通知开启时，每条新意见入队一次，通知类型为 `feedback`；关闭时仍保存意见，不排队，重新开启不补发关闭期间的意见。新增投票继续采用原有汇总卡片，改投／取消不新增提醒；手动“立即推送汇总”仍只汇总票数。

意见卡片包含品牌、类型、可选城市、完整正文和北京时间。用户内容放入飞书JSON 2.0的 `plain_text` 组件，后台页面用 `textContent` 渲染，不将用户输入解释为HTML、Markdown链接或群成员提及语法。消息不附带IP、匿名访客标识、请求标识或机器人凭据。飞书组件依据见[官方纯文本组件文档](https://open.feishu.cn/document/feishu-cards/card-json-v2-components/content-components/plain-text)。

通知使用既有持久队列异步发送，传输失败不撤销已保存意见。可重试失败最多尝试5次，间隔5／30／120／600秒；最终失败可由管理员查看并手动重试。网络超时可能出现服务端已接收但本机未获确认，重试可能产生重复消息，因此不承诺群消息恰好送达一次。关闭通知会取消尚待处理的任务，已在发送中的请求可能完成；标记意见已看不等于取消通知。

## 数据与隐私边界

“匿名提交”表示不要求登录、姓名或联系方式，不表示无法关联访问。意见正文、分类、城市、状态、创建时间与匿名访客摘要、提交标识存入私有SQLite的 `campaign_feedback` 表，只有登录管理员可读取列表。正文可能包含用户自行输入的个人信息，运营人员应按实际内容处理。

限流保存来源IP的派生键：成功额度使用数据库私密密钥生成的HMAC，请求级保护沿用现有IP摘要。意见表不保存原始IP，但反向代理访问日志仍可能包含IP；不能把本模块的存储范围当成整个服务器的无日志保证。机器人开启时，运营群会收到完整意见正文、类型、城市和时间，页面提交处已提示同步运营群。

本版未设置意见正文的自动过期、用户自行删除或后台删除入口。已看意见继续保留；通知历史的清理不等于删除意见正文。运行库、通知队列与备份均可能含意见内容和私密配置，须保存在非公开目录，不提交Git或用于公开截图。

## 升级与验证

新库和旧库启动均通过 `CREATE TABLE IF NOT EXISTS` 增加意见表及索引，不重建原投票、统计、账号、海报或机器人配置。意见关联 `campaign_visitors`，后续清理访客时必须考虑该外键，不能直接删除仍有意见的访客。

按[Ubuntu部署说明](../deploy/ubuntu/README.md)制作精确提交的源码包，以 `--revision` 选择版本，停服后使用SQLite backup API保存私密升级前快照。自动失败回退仅处理代码与配置，不自动恢复数据库；回退旧通知代码前还需评估新增 `feedback` 队列类型的兼容性。常规完整备份同时覆盖数据库和媒体，恢复旧快照前检查通知队列，避免重发历史待发任务。

实现与自动检查入口：[意见存储](../backend/campaign_feedback.py)、[HTTP接口](../backend/campaign_http.py)、[飞书队列](../backend/campaign_feishu.py)、[意见箱测试](../tests/test_campaign_feedback.py)。隔离测试覆盖校验、幂等、配额、管理员权限、状态筛选、旧库新增表及通知纯文本等场景；模拟传输不等于真实群投递验收。不要用正式意见、正式投票或真实机器人发送作为只读健康检查。
